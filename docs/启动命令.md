# 启动命令速查

> 日期：2026-09-30 ｜ 维护：小宋
> 定位：日常开发的命令手册。环境 = conda `fast`（E:\conda\envs\fast，Python 3.10.20），终端 CMD。
> ⚠️ 所有命令都在 `(fast)` 激活后的项目根 `F:\price-agent` 下执行。

---

## 1. 环境准备（每次开终端）

```cmd
conda activate fast
cd /d F:\price-agent
```

## 2. 后端启动

### 日常开发（推荐）

```cmd
python -m uvicorn app.main:app --port 8000 --reload --no-access-log
```

| 参数 | 作用 |
|---|---|
| `python -m uvicorn` | 用 `(fast)` 环境里的 uvicorn（Windows conda 下最稳的调用方式） |
| `--reload` | 改 `.py` 自动重启（开发期专用） |
| `--no-access-log` | 关掉 uvicorn 原生的状态码行——它没有时间戳、没有 trace_id，会和 `app.access` 的访问日志重复 |

### 备选：`fastapi run --port 8000`

功能正常，**但控制台不会显示 `app.access` 访问日志**（fastapi CLI 的 rich 终端接管会吞掉它，2026-09-30 实测确认）。
不看日志时（挂着联调）用哪个都行；要看日志就用上面那条。

### 生产式启动（验收 / 压测）

```cmd
python -m uvicorn app.main:app --port 8000 --no-access-log
```

（不开 `--reload`，行为最接近真实部署。）

## 3. 前端启动（另开一个终端）

```cmd
cd /d F:\price-agent\frontend-web
npm run dev
```

- 浏览器进 vite 提示的端口（5173 或 5174）。
- Vite 已配置代理：`/auth` → `127.0.0.1:8000`，所以**后端必须在 8000 端口**起，前端登录才通。
- 前端测试：`npm test`（node --test）。

## 4. 数据库迁移（改了 `app/models/` 之后）

```cmd
:: ① 生成迁移（生成前先 git pull + alembic upgrade head，防止分叉）
alembic revision --autogenerate -m "英文短描述"

:: ② 逐行读生成的文件（autogenerate 盲区清单见 AGENTS.md §4）

:: ③ 执行
alembic upgrade head

:: ④ 完成判据：两个命令打印同一个 revision id
alembic current
alembic heads
```

规则详见 `AGENTS.md`（§2 开工三步 / §4 标准动作 / §5 迁移分叉处理）。

## 7. 常见问题

| 现象 | 原因 / 解法 |
|---|---|
| 前端登录不通 | 后端没起在 **8000** 端口，或 vite 代理指向被改（应指 `127.0.0.1:8000`） |
| 控制台看不到访问日志 | 检查是不是用 `fastapi run` 启动 → 换 §2 的 uvicorn 命令 |
| 端口被占 | `netstat -ano | findstr :8000` 找 PID → `taskkill -F -FI "PID eq <pid>"` |
| `alembic heads` 出两行 | 迁移分叉了，处理见 AGENTS.md §5 |
