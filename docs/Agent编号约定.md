## 4. 🔴 A1 已经落地：`app/agents/a1_graph.py`（2026-10-18 大宋拍板改名）

### 4.1 为什么从 `rag_graph` 改名

原名是在只有「检索」一个节点时起的。加进对比 / 推荐 / 卡片节点后会**名不副实**——
而且 **`decide` 节点从一开始干的就是 A1 的活**（§1 定义 A1 =「理解 / 路由（主管）——
判断用户这句话该交给谁」）：它调模型、看模型决定调什么工具、决定调几次。
**RAG 只是它目前掌握的一个工具。**

继续叫 `rag_graph` 会让后面的人困惑：「为什么对比功能在 RAG 文件里？」

**改名时机**：只有 2 个节点、20 处引用时改最便宜。等 A4/A5/卡片都加上去
（工具清单 4 个、引用点更多）就烦了。**这跟 `RECURSION_LIMIT` 是同一个道理：
改一个数越早越便宜。**

### 4.2 现行结构

```
app/agents/a1_graph.py：
    START → decide ⇄ search
              ↓
             END
```

| 节点 | 职责 | 状态 |
|---|---|---|
| `decide` | **A1 本体**：调模型（带工具定义），让它决定调哪个工具、调几次 | ✅ 已实现 |
| `search` | 执行 `rag_service.retrieve_relevant`（RAG 检索） | ✅ 已实现 |
| `compare` | A4 参数对比（分维度） | ⬜ 设计见 `docs/A4对比与A5推荐-设计.md` |
| `recommend` | A5 推荐（走博查联网） | ⬜ 同上 |
| `card` | 商品卡片 | ⬜ 设计见 `docs/对话侧商品卡片-设计.md` |

### 4.3 🔴 为什么所有工具必须在同一个图里（硬约束，不是偏好）

把 compare 独立成另一个图 → 它与本图之间**没有状态通道**，`messages` 传不过去
→ 得自己造队列 / 缓存 → **那就是手写编排**
→ 又回到「在一个用编排框架的项目里手写编排」（大宋 2026-10-17 撤回「固定前置」的理由）。

**所以「独立成Agent」指的是「独立节点 + 独立 prompt + 独立判断逻辑」，
不是「独立成图」或「独立成服务」。**

### 4.4 A1 与各能力的关系

| 能力 | 是不是 Agent | 说明 |
|---|---|---|
| **A1 路由** | ✅ **是**（本体） | `a1_graph.py` 的 `decide` 节点 |
| RAG 检索 | ❌ 是**工具** | A1 的一个工具，由 `search` 节点执行 |
| A4 对比 | 🔶**独立节点** | 有自己的 prompt + 维度判断，但不是「Agent」（不独立编排） |
| A5 推荐 | 🔶**独立节点** | 同上 |
| A2′ 商品情报 | ❌ 是**工具** | 能力在 `spec_complete_service`，卡片形态时挂到 A1 |
| A6 画像 | ❌ **独立后台任务** | `BackgroundTasks` 每轮异步跑，**不在图里** |

⚠️ **「独立节点」和「Agent」的界线**：本文说的独立节点都是**被 A1 调度的**，
不自己决定调谁。**真正的 Agent 特征是「有自主决策权」**——
目前只有 A1 有（它决定调哪个工具）。这个界线将来如果变了要回来改本文。
