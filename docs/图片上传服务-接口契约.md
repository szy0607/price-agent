## 1. 接口

### `POST /upload/image`

- 鉴权：`CurrentUser` + `require_same_origin_write`（同其他写接口）
- 限流：每用户 60 秒 10 次，超限 `42901`（进程内滑动窗口，`app/core/rate_limit.py`）
- Body：`multipart/form-data`，字段 `image`

**落盘前五道闸**（`app/services/image_store.py`）：

| 闸 | 规则 | 拒绝 |
|---|---|---|
| 分块读 | 64KB 累加计数，超 2MB 即断（不信 `image.size`，chunked 传输下它是 None） | 40001 |
| 扩展名 | 白名单 `.jpg/.jpeg/.png/.webp` | 40001 |
| 大小 | ≤ 2MB | 40001 |
| 尺寸 | **解码前**查 `im.size`，总像素 > 2500 万即拒（解压炸弹防线；`Image.MAX_IMAGE_PIXELS` 同步压低兜底） | 40001 |
| 可解码 | `im.load()` 触发完整解码，假文件在这露馅 | 40001 |

通过后：EXIF 转正 + 重编码 JPEG（剥 GPS）+ 缩到最长边 1280 + quality 85；**原子写入**（`.<name>.tmp` → `os.replace`，半文件永不出现在服务路径）；文件名 `uuid4().hex + .jpg`。

**响应**（`code=0`）：

```json
{ "code": 0, "msg": "success", "data": { "id": 12, "image": "/uploads/ab12cd34.jpg" } }
```

- `id`：image 表主键（登记簿行）
- `image`：相对路径，直接回填添加表单的图片字段

### `GET /uploads/{name}`

- 鉴权：`CurrentUser`（未登录 40101）
- `name` 必须匹配 `^[0-9a-f]{32}\.jpg$`（同时是路径穿越防线）
- 归属：查 image 表 `path` → `user_id` 等于当前用户才放行
- 图不是你的 / 未登记 / 文件不在：一律 `40001 "图片不存在"`——与 purchase-records「别人的 id 一律不存在」同口径，**不透出可枚举差别**
- 成功：`FileResponse`，`content-type: image/jpeg`

## 2. 生命周期（image 表）

```
pending ──保存商品──> referenced ──删/换图且无人引用──> released ──定时清理──> (删行删文件)
   │                                                                    ↑
   └── 24h 无人认领 ──────────────────────────────────────────────────────┘
```

| 状态 | 含义 | 进入时机 |
|---|---|---|
| `pending` | 已上传，无商品引用 | `register_upload`（上传即登记，从第一秒起有主） |
| `referenced` | 被 cart_item / owned_item 引用 | 商品保存/换图时（仅 pending → referenced，不覆盖已有 referenced） |
| `released` | 两张 item 表都无引用 | 商品删除/换图后（`release_if_unreferenced` 双表扫描） |

**关键口径**：

- **释放必须同时扫 `cart_item` + `owned_item`**——双导航共用图，只扫一张会误删在用的图
- **`transfer`（购物车 → 物品库）天然安全**：owned 顶替 cart 引用同一 path，不走删除路径，状态 referenced 不变
- **多 item 共享**：计数逻辑保证最后一个引用删除后才 released（测试 `test_shared_image_survives_until_last_reference_gone` 背书）
- **清理幂等**：删 stale pending（>24h）+ released；行不在跳过、文件不在跳过

## 3. item 表的 image 字段校验

`CartItemInSchema` / `CartItemUpdateSchema` / `OwnedItemInSchema` / `OwnedItemUpdateSchema`
的 `image` 字段统一过 `validate_image_path`：必须匹配 `^/uploads/[0-9a-f]{32}\.jpg$`。
挡两类注入：`../` 路径穿越、`http(s)://` 外域引用（后者会被前端 `<img>` 直接加载）。

## 4. 错误码（不新增第八个）

| 场景 | 错误码 |
|---|---|
| 假扩展名 / 超 2MB / 炸弹尺寸 / 不可解码 / 空文件 | 40001 |
| 限流（60s 11 次） | 42901 |
| 未登录上传/下图 | 40101 |
| 下图越权 / name 形态错 | 40001「图片不存在」 |

## 7. 已知边界（有意为之，不是漏）

- 限流是进程内字典：多 worker 各自为政，搬 Redis 的触发点是「上多 worker」
- 清理间隔 1 小时：released 的图最长存活 1 小时+，期间仍可被原主人下图（行还在、owner 未变）
- `image.id` 目前只作登记簿主键返回给前端，访问收口走 path——前端将来要用 id 形式可再加端点，现在的形态已满足「传了图就有主、越权读不到」
